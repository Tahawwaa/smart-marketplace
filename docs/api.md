# قرارداد API

اندپوینت‌های کاتالوگ پیاده‌سازی شده‌اند؛ سایر بخش‌ها هنوز پیشنهادی‌اند.

## مسیر پایه

`/api/v1`

آدرس نمونه توسعه: `http://localhost:8000/api/v1`

## منابع اولیه

| قابلیت | مسیر | وضعیت |
| --- | --- | --- |
| دسته‌بندی‌ها | `GET /categories` | پیاده‌سازی‌شده |
| دسته‌بندی | `GET /categories/{slug}` | پیاده‌سازی‌شده |
| محصولات | `GET /products` | پیاده‌سازی‌شده |
| محصول | `GET /products/{slug}` | پیاده‌سازی‌شده |
| سبد خرید | `/cart` | پیشنهادی |
| سفارش‌ها | `/orders` | پیشنهادی |
| کاربر فعلی | `/user` | پیشنهادی |

## پارامترهای فهرست محصولات

| پارامتر | نوع | توضیح |
| --- | --- | --- |
| `category` | slug | شامل همه‌ی زیرشاخه‌های دسته |
| `brand` | slug | فیلتر برند |
| `vendor` | slug | فقط محصولاتی که این فروشنده موجودی فعال دارد |
| `search` | string | جست‌وجو در نام و توضیحات |
| `min_price` / `max_price` | integer | بازه‌ی قیمت مؤثر (`sale_price` یا `price`) |
| `attrs[slug][]` | string | مقادیر ویژگی؛ فقط تنوع‌های فعال |
| `sort` | enum | `newest` \| `price_asc` \| `price_desc` \| `name` |
| `per_page` | integer | پیش‌فرض ۱۵، حداکثر ۱۰۰ |

پارامترهای نامعتبر با وضعیت `422` و جزئیات در `errors` برگردانده می‌شوند. محصول
غیرفعال در فهرست نمایش داده نمی‌شود و در جزئیات `404` می‌گیرد.

## پاسخ‌ها

- پاسخ موفق: داده اصلی در کلید `data`.
- فهرست صفحه‌بندی‌شده: `data` به همراه `links` و `meta`.
- خطا: توضیح در `message`.
- خطای اعتبارسنجی: وضعیت HTTP برابر `422` و جزئیات فیلدها در `errors`.
- پاسخ بدون محتوا: وضعیت HTTP برابر `204`، بدون بدنه.

## اتصال و دسترسی

- کلاینت فرانت‌اند هدر `Accept: application/json` ارسال کند.
- مبدا مجاز فرانت‌اند در تنظیمات CORS بک‌اند مشخص شود.
- گروه میدل‌ور `api` فعال است و محدودکننده‌ی نرخ `api` روی ۶۰ درخواست در دقیقه تنظیم شده است.
- روش احراز هویت پیش از پیاده‌سازی تعیین شود؛ برای SPA متعلق به همین پروژه، احراز هویت مبتنی بر کوکی با Sanctum گزینه پیشنهادی است.
- در صورت انتخاب کوکی، تنظیمات credentials، CSRF و دامنه‌ها هم در فرانت‌اند و هم در بک‌اند هماهنگ شوند.
- مجوز دسترسی و اعتبارسنجی همیشه در بک‌اند اجرا شود.
